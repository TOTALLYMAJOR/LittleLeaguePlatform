## Defects (must fix before publish)

- **P1-1 — Timezone bug in diff formatting, with a TZ-fragile test.** `formatTime` in `lib/supabase/event-change-log-reads.ts:311-314` formats in the *server process* timezone (no `timeZone` option, server component). A UTC-deployed server shows families shifted event times; the ChangeBand's own timestamp formats client-side, so one row can mix two timezones. Reproduced: `TZ=UTC npx vitest run lib/supabase/event-change-log-reads.test.ts` → 1 failed. Any UTC CI runner fails the suite. Fix: format against the league/event timezone (or pass ISO to the client and format there); pin `TZ` in vitest config either way.
- **P1-2 — `location_changed` events silently never reach parents (TS write path).** The writer's `after_json` select in `lib/supabase/schedule-management.ts:698` omits `field_location_id`; the reader skips undefined fields and `location_changed` is not in the zero-diff passthrough list (`event-change-log-reads.ts:247,272`), so a field move with an unchanged venue name produces no visible change. The SQL RPC writer (`to_jsonb`) behaves differently — same user action, different outcome by write path. Fix in the adapter (add `location_changed` to the passthrough or synthesize a "Location changed" line when diffs are empty) — the writer itself is outside this slice's boundary.
- **P2-1 — Honesty inversion for legitimately-empty scopes.** Parents with team-membership-only access (no `player_guardians` row) or teams with zero events hit `ok:false` branches and see the "Changes could not be checked" warning forever, though nothing failed (`event-change-log-reads.ts:158,167,196`).
- **P2-2 — Unbounded reads.** The events query has no date window, limit, or status filter; the SQL `limit` applies before JS filtering, so relevant changes can drop with no signal and stale changes occupy slots.
- **P2-3 — Acceptance item 6 unmet and undisclosed.** The 08.F.1 upgrade of `scripts/verify-theme-contrast-proof.mjs` (authenticated, all family routes, light mode, regression fixtures) was not made; `scripts/` diff is empty across the range; no contrast artifact exists for the slice; no doc lists the gap as debt (LP-UX-001's evidence block cited its contrast run; LP-UX-002's silently drops the line).
- **P2-4 — Acceptance record overstates its artifact.** The cited proof (`output/playwright/lp-ux-002-family-shell/proof.json`, 80 results) is the *unchanged LP-UX-001 shell harness* re-run into a renamed directory. It asserts shell-contract metrics only — nothing about ChangeBand, passport, RSVP control, readiness strip, filter, or watermark; the What Changed band renders in none of the 80 captures; `/parent/rsvp` and `/parent/transportation` appear in the Features.md route list but not in the sweep; "done-local-accepted" names no independent accepting party (same author, same day, evidence column citing its own commit's doc).
- **P2-5 — Brief acceptance item 1 only partially met at 390px.** In both the committed artifact and my independent capture, the 390px first viewport ends mid-passport: inline RSVP and the readiness strip sit below the fold (header context table + filter + stat tiles consume the top). Order is correct; fold budget is not.
- **P1-3 — Retired focus ring still governs every new component (04 §7, 08 A.1/B.3).** `parent-weekly.css:476-483` keeps `outline: 3px solid rgba(255,122,47,0.48)` and its `.parent-weekly-dashboard`-scoped specificity beats the conformant global ring, so FamilyFilter, ChangeBand, ReadinessStrip, RsvpControl, and passport links all inherit it. Computed ~1.6:1 on light surfaces and ~2.2:1 on the navy passport — below the 3:1 non-text floor. axe has no focus-appearance rule, so the zero-violation artifact does not cover this. 04 §7 required this exact ring's replacement.
- **P1-4 — Deep-operations contents are not all reachable at canonical routes (brief acceptance item 5).** The `<details>` removal is correct, but `FamilyMissionControlClient`, `FamilyFlightPlanClient`, and `ParentNotificationReceiptsClient` are now mounted on no route (only their own tests reference them). Receipts remain reachable via Communication Room and transportation state via the passport, but the **family flight-plan handoff workflow has no UI anywhere** while its data is still fetched and fed into `buildFamilyMissionControl`. Either mount the handoff capability at a canonical destination (07 dispersal plan: passport responsibility row) or record its retirement as an explicit decision — silent orphaning is neither.
- **P2-6 — `.parent-rsvp-glow` not retired from slice routes (04 §1, 08 B.1, Stage B task 8).** The Tailwind-green `#22c55e`, 42px (compact 34px), weight-950 control still renders on `/parent/schedule` (`ParentScheduleFeed`) — listed in the Features.md row as a slice route — and on `/parent`'s degraded-access fallback (`ParentDashboardClient`).
- **P2-7 — Readiness lanes incomplete and one lane fails 06 §7 honesty.** No unacknowledged-critical-messages lane despite receipts being in scope; RSVP/ride lanes derive from the single next event only (no per-child union under "Everyone"); and `!transportationAssigned` is unconditionally unresolved — a family that never requested ride help is told "Ride responsibility is not fully assigned" instead of the required neutral "No ride help requested" state.
- **P2-8 — Zero test files for `components/family/*`.** The 409 UI copy, success-fact message, watermark suppression, "viewing never acknowledges" absence-of-write, the green "Nothing unresolved" state, and `aria-pressed` semantics are all unasserted; the five dashboard tests cover them only incidentally via SSR string matching.
